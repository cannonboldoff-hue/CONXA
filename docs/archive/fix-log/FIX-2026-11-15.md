# Fix Log — 2026-11-15

**A new version of the part that runs workflows on customers' computers is out — 2026-11-15**
The small program that starts workflows on a customer's computer got a fix so it cleans up its old versions correctly and never deletes the one in use or the one before it. It is released as version 3.2.3, and future updates now wait for computers to have it. While releasing, the automatic safety run caught a practice page that finished an upload too instantly to prove anything, so that page now behaves like a real upload.
— 2026-11-15

**A repeat can now carry a whole table of values — 2026-11-15**
A workflow that repeats once per item could only carry one value per item, such as a file name. It could not carry a recipient and a subject together. You can now give it a small table, one row per repeat, and each row's values are used in that repeat. If a row has a blank value, nothing runs at all. Older copies of the app refuse such a workflow instead of quietly doing the wrong thing.
— 2026-11-15

**Sign-in checks and form labels read more of the page — 2026-11-15**
Some sites answer a visitor with an error page at the very address Build Studio used to check sign-in, so it learned nothing. It now also looks at how the page itself answers, and tries the page you land on after signing in. Separately, a form box whose label shows up a moment late, or sits after the box, now gets that label recorded.
— 2026-11-15

**Buy and pay buttons are treated as the point of no return — 2026-11-15**
A button called "Buy now" or "Complete purchase" was handled like any ordinary click, so a test or a repeat run could press it without asking first. These buttons now count as steps that cannot be undone, the same as "Place order" already did. Ordinary buttons such as "Purchase history" are not affected.

The "Finish and save" button on an empty recording also now explains why it is greyed out.

**Steps that pick a row from a list are checked more carefully — 2026-11-15**
Conxa used to tie almost every click to "its row" using any text in that row, even a price shared by two products or the button's own label, so a perfectly good step could refuse to run. Now a row is used only where it is needed, it is named by something that appears in that row alone, and a step that can't be undone asks you "is this the row you mean?" in the chat instead of showing an internal error and leaving you stuck.

**A click that never reached its button no longer counts as done — 2026-11-15**
A click could be sent, land on a banner in front of the button or on nothing, and the test still said it finished. A banner that covers a button and cannot be closed used to end the test as "Done, please check" without any click happening; it now fails with "Another element was covering the target", and a banner Conxa knows how to close is closed and the click lands. Conxa also asks the page where the click went; if it did not reach the button, the step fails in plain words and the pop-up helper gets its chance. A drag that had nothing to pick up also fails loudly instead of doing nothing, and an address that still contains an empty placeholder is refused instead of being opened.

**Menu items that only appear when hovered are now found — 2026-11-15**
Some menus show their items only while the mouse rests on the menu, and recordings don't keep that hover unless it was switched on. When a button never shows up, Conxa now moves the pointer over the parts around it, the way a person would, and tries again. If it still does not show up, the step fails as before.

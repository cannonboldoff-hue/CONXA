## How tokens were minted (no real Clerk)
`wf20_mock.py` holds a fresh RSA test key, serves it at `/.well-known/jwks.json`, and `/_mint?sub=&org=&role=&ttl=` returns an RS256 JWT with `iss`=mock, `client_id=wf20-client`, `org_id`/`org_role` (company A = `org_a`, company B = `org_b`, plus a fresh org per plan row). The backend's real `verify_clerk_jwt` checks it. `ttl<0` makes an expired token. Seat counts come from the mock's `GET /v1/organizations/{id}/memberships`; the backend's calls to `api.clerk.com` are redirected to the mock by `wf20_site/sitecustomize.py` (test hook via PYTHONPATH, no product file touched). Plans are changed with the real `POST /api/v1/entitlements/admin/billing` + admin token.

## S0 findings (20.2, stop the campaign per spec; security issue)
1. **Any signed-in user reads and cancels another company's video-analysis jobs.** `GET /api/v1/jobs`, `GET /api/v1/jobs/{job_id}`, `GET /api/v1/jobs/{job_id}/events`, `POST /api/v1/jobs/{job_id}/cancel` do no workspace check (`app/api/job_routes.py`; `video_routes.py` even notes "the generic reads don't check the caller"). Repro: B (`org_b`, Pro, token type: Clerk JWT, org admin) `POST /api/v1/video/analyze` -> job id; A (`org_a`, Pro JWT) `GET /api/v1/jobs` -> 200 with B's job, `resource_id: org_b` and `result.segments[0].visible_target` = B's screen text ("SECRET screen text..."). `GET /jobs/{id}` -> 200 same. Cancel on a running job would stop B's work.
2. **Company A can replace company B's installer.** `POST /api/v1/workflows/{slug}/installer/upload?version=9.9.9&release_notes=x` (legacy route; slug comes from the URL, no ownership check, `app/api/publish_routes.py::_upload_installer_impl`) with A's admin JWT and B's slug `org_b` -> 200; afterwards `GET /api/v1/installers/org_b` returns A's bytes. Whatever B's customers download is now A's file. (B's own "versions" list hides A's row, so B may not notice.)
3. **Company A can write company B's governance policy.** `PUT /api/v1/tracking/{B workspace_id}/policy` with A's Pro admin JWT, body `{"denied_hosts":["evil-a-wrote-this.example"],"enforce":true}` -> 200 `policy_version 2`; B fetching its policy now gets A's host list with `enforce:true` (`tracking_routes.py::put_governance_policy` never compares the path workspace_id with the caller's).

## Other findings
4. **S1** Pro/Enterprise can be blocked from compiling by AI-credit use. The proxy's monthly token quota (`llm_proxy_monthly_token_quota`, 5M) counts every usage class but only refuses `compile`. Pro workspace with >5M tokens of AI-credit use: compile call -> 429 `quota_exceeded` while compile credits remain (20.7).
5. **S2** `GET /entitlements/current` and `POST /usage/compile/{reserve,commit,release,refund}` wrap `current_principal()` in `try/except Exception -> entitlement_http_error`, which turns the 402 `seat_limit_exceeded` into 503 `entitlements_unavailable`. The over-seat person sees "try again in a moment" (20.9).
6. **S1 (not part of a row, found while testing 20.2)** The runtime's policy fetch `GET /api/v1/tracking/{ws}/policy` sends only `X-Tracking-Token`, but with auth on the request needs a Clerk bearer: tracking token alone -> 401 `missing_bearer_token`. Governance policies cannot reach installed runtimes in a signed-in deployment (`security.py` public list has only POST `/events`).
7. **S1, gate verified, real delivery BLOCKED** `POST /api/v1/subscriptions/webhooks/cashfree` and `/cashfree-orders` are not in the public path list, so a webhook with no bearer is refused 401 by the sign-in gate before its own signature check. Cashfree cannot send a Clerk token. Needs Cashfree sandbox to confirm end to end.
8. **S3** Every authenticated request fetches the identity provider's JWKS afresh (606 fetches in one run); identity-provider outage -> every user gets 401 "session expired". Several refusals show the raw code as the message (`workflow_limit_exceeded`, `ops_tier_required`, `distribution_not_permitted`, `byok_requires_enterprise`) instead of plain words. A single LLM call can overshoot the AI pool (Pro pool 10M ended at 11.25M). Reservation TTL has a 60 s floor.
9. **S3** Public, unauthenticated `POST /api/v1/telemetry/runtime-start` writes a row keyed by `company:install_id` for any company name (documented as accepted risk). Public `GET /api/v1/updates/*` makes the server call github.com.

## Root causes and decisions (engineering owner, 2026-11-23)

**One general cause behind a, b, c (and two more found by grepping every route that takes a company/job/resource id):** a route trusts an id the caller sends (URL path or body) and never compares it with the caller's own workspace. The codebase already has the right pattern: derive the slug from the token (`workspace_dir_slug(principal.workspace_id)`, used by every v2 route and `release_routes.py:80 _require_owned_slug`), or compare a stored owner with `principal.workspace_id` (`cashfree_routes.py:582` add-on verify, `video_routes.py:80`, `workflow_routes.py:96`). The fix moves that comparison into one shared helper in `app/api/deps.py` (next to `current_principal`) and calls it from every write route that takes a company id in its path; nothing new is invented.

Route sweep (all `{...}` routes plus body-id routes): app-graph, release, skill-pack delta/artifacts, tracking runs/run/reconcile/workflow-detail/drift, workflow get/delete, bundle release, compile reserve/commit/release/refund, machine revoke, execute-grant revoke, add-on verify, BYOK, execute_chat target, are all scoped (path value only used together with a visibility filter or a stored owner). Not scoped: the five below.

```python
def own_workspace_slug(principal: Principal, path_value: str) -> str:
    """A company id taken from a URL must be the caller's own workspace (id or slug form). Returns the slug."""
    own = workspace_dir_slug(principal.workspace_id)
    if path_value not in (principal.workspace_id, own):
        raise HTTPException(status_code=403, detail="workspace_forbidden")
    return own
```

- Environment: normal stack was up at start (backend :8000, fixtures :8099, Studio on a random CDP port, dev lane, skip-auth). Execute was tested in an ISOLATED setup that never touches the owner's `%APPDATA%\conxa-execute`:
  - Execute (dev, `npm`-less launch of `conxa-execute/app` + vite on :5175) with its own profile `%TEMP%\wf19\exec-profile`, started by `docs/testing/tools/wf19_exec_up.ps1`.
  - Isolated runtime install `%TEMP%\wf19\rt` (built with `tools/wf17_install.py`, skills trimmed to `wf17-a-only`, `wf17-slow`, `wf17-signout`, one app "App A" = `wf17_authsite.py` on :8101, a cookie-login site). Runtime host exe = Studio sandbox copy, app layer = fresh `deps/conxa-app` build `app-v0.0.0-local.20261122212900`.
  - **MOCK sign-in (not Clerk):** `tools/wf19_mock_clerk.py` on :8110 (PKCE checked, RS256 JWTs, JWKS, Clerk Backend API stand-in for organisations, account chosen by callback port so Studio and Execute get different people). A second copy of the REAL cloud backend on :8120 with auth ON (`tools/wf19_backend.py` skips only the "production config complete" startup check), its own data dir, and `api.clerk.com` redirected to the mock (`tools/wf19_site/sitecustomize.py`). So Execute's real PKCE code, the real JWT check, the real `/execute/contexts`, grants, pool metering and proxy checks ran. Real Clerk was NOT used and no real account was touched.
  - **MOCK model (not an LLM):** `tools/wf19_mock_llm.py` on :8130, OpenAI-compatible, scripted ("what skills" -> list_skills tool call, "run X" -> execute_skill). Plugged in as the cloud's Free pool (`LLM_FREE_ENDPOINT`). No real provider key exists on this machine. It proves streaming, tool calls, the confirm card, run start and metering, not answer quality.
  - Sign-in "browser": Execute's `shell.openExternal` is replaced by `tools/wf19_openext.js` (preloaded via NODE_OPTIONS): the mock URL is followed like a person who approves, anything else is only logged (the owner's Chrome never opened).   - Large-window runs: at the normal window size every run fails (finding F1). To test 19.6-19.8 at all, Execute was started with `--force-device-scale-factor=0.5` and maximised (page area ~3840x2040 CSS px, so the browser pane is bigger than 1280x720 CSS px). Rows say which size they ran at.

**F1 — Execute's panel shrinks the page with an emulation `scale` (S1).**
- Root cause: `conxa-execute/app/electron/browser_panel.js:109-116` `_emulate` sends `setDeviceMetricsOverride {..., scale: run.scale}`; `setActiveBounds:443-449` sets `run.scale = min(rect.w/1280, rect.h/H, 1)`. CDP input is not mapped through that `scale` (clicks land at 1/scale), which is exactly what `runtime/app/page_geometry.js:110-121::inputLands` rejects; `checkGeometry` asks `ensure_geometry`, which re-applies the same scale, so the run dies before step 1. The current panel test even pins the bug (`electron/test/browser_panel.test.js:98-112` expects `scale: 0.5`). Studio fixed the same thing for test runs (TRD §4.7a "Page size"); Execute was left on the old path (TRD lines say "Execute's panel ... letterboxes" / "pins its page size with a metrics override").
- Also, `_viewport:152-157` drops the runtime's `fit: "width"` (`runtime/app/browser.js:1069,1118` always sends it), and views are parked at 0x0 (`_HIDDEN` at 241, 434, 452, 466, 499), which only "worked" because the override held 1280 regardless of view size. Under zoom a 0x0 view is a 0-wide page, so both must change together.
- Studio's reference (`conxa-builder/electron/browser_panel.js`): zoom factor for runtime-driven runs (`_setZoom`/`_emulate` 154-177), height follows the pane with `fit: "width"` clamped to `MIN_H 480`/`MAX_H 1440` (`_fitBox`/`_layout` 833-891), hide with `setVisible(false)` and keep bounds (`_hideView` 53, `hideAll` 932), a zero rect means hide (`setActiveBounds` 855), a new tab is placed at once from the run's rect or the last pane rect (391-394, `_lastRect`), minimized window holds the page by an override at zoom 1 (`setMinimized` 182-197, wired in `main.js:520-521`), tolerant `_ensureGeometry` for zoomed pages (215-219).
- Fix (port Studio's pattern; no change to `page_geometry.js`, `checkGeometry` or `inputLands`; width stays 1280; only the panel sets size):
  1. `_viewport` keeps `fit: "width"`; add `const MIN_H = 480, MAX_H = 1440;` and `run.height`, `run.rect`.
  2. `_emulate(run, tab)`: if the window is minimized **or the run has no rect yet**, `setZoomFactor(1)` + override `{width:1280, height: run.height, deviceScaleFactor:1, scale:1}` (scale 1, so input lands); otherwise clear the override if this tab held one, then `webContents.setZoomFactor(run.scale)`. Never send `scale != 1`.
  3. Replace `setActiveBounds`'s letterbox with Studio's `_layout` + `_fitBox` (no-`fit` viewport from an older runtime still letterboxes, but with zoom). Invalid/zero rect -> `hideAll()`.
  4. Views are hidden with `view.setVisible(false)` and keep their bounds in `setActiveBounds` (other runs), `hideAll`, `setVisibleChat`, and background tabs; only the shield still uses `_HIDDEN`. `_createTab` places the new tab from `run.rect || _lastRect` instead of leaving it at 0x0.
  5. `_ensureGeometry` fits check: width within 1 px of 1280 and height within 2 px of `run.height`, any DPR (mirror Studio 217-219); `ensureGeometry` re-lays the run out from `run.rect` when the first check fails (Studio 235-239).
  6. Export `setMinimized`; `conxa-execute/app/electron/main.js` (after line 115): `mainWindow.on("minimize", () => void browserPanel.setMinimized(true))`, `on("restore", ... false)`.
- Wording (runtime, shared by both apps): `runtime/app/run.js:160-162` names "Build Studio" and "test". New text, keeping the phrases Studio's `failure_summary.py:38-41` and tests match on: PAGE_SIZE = "The browser is not showing the page at its normal size, so a click could land in the wrong place and this step could not be trusted. If the window is minimized, bring it back, then run it again." PAGE_HIDDEN = "The window showing this run's browser is minimized or hidden, so the page could not be shown and this step could not be trusted. Bring the window back and run it again." Studio keeps its own Studio-specific rewrite.

**F2 — a tool-call-only stream is treated as empty, retried and billed 3x (S1, money).**
- Root cause 1: `conxa-cloud/backend/app/llm/router.py:647-650` collects only `text` items into `full_text_parts`; `:680` `if not full_text:` then returns None (`:703-705`) for a valid tool-only turn, and `_route:436-440` retries on another entry/model.
- Root cause 2 (general): `route_text`'s docstring (`:462-464`) promises "a failure mid-stream (after some chunks already reached `on_delta`) is not retried", but nothing enforces it: any None after deltas were forwarded retries, and the client concatenates both attempts (`{}{}{}`, doubled text or reasoning).
- Fix: (a) in the streaming branch track `saw_tool_call` from `item["type"] == "tool_call"`; empty = `not full_text and not saw_tool_call`. (b) In `_route`, wrap `on_delta` with a counter; after a None result, `break` instead of retrying when the counter is > 0 (a retry would repeat what the caller already has and bill again). Non-streaming path needs no change: it only fails fast on `finish_reason == "length"`, a tool-only reply (`finish_reason "tool_calls"`) passes.
- Metering: `conxa-cloud/backend/app/api/llm_proxy_routes.py:357-361,391` estimates output tokens from text only, so a tool-only turn is metered at ~0 output tokens. Also collect `name` + `arguments_delta` of tool_call items and estimate on `full_text + tool text`. Still metered once per turn.

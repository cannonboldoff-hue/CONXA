## Implementation plan
Scope this round: items 1-5 (F4, F5, F3, F6, F7, plus the cheap F2/F8 banner fix). Deferred to TODO.md: 18.2 lock-wait feedback, CLI resume check (host exe), F1 authoring (owner decision), F9.

1. **One hand-over wait for both sites, with resume revalidation (F4, F5, F6, F3, cancel leak)**: `runtime/app/run.js`.
   - Add a helper `waitForPerson(ctx, state, step, i, page)` and use it in the `handover` branch (`run.js:955-980`) and in the on_missing "ask" branch (`run.js:1325-1336`). It arms, then races the signal against `HANDOVER_INCALL_MS` and `ctx.cancelCheck` (poll it like `raceCancel`). On a signal it disarms and returns. On cancel it disarms and throws `cancelled`; today the listeners stay open after Stop. When the wait expires and `state.loopDepth > 0 || state.forkDepth > 0 || handover.noPark()`, it disarms, emits `step_fail {fc: "handover_timeout"}` and throws `stepFailure` with `{handoverFailed: true, handoverTimedOut: true}`. The message: "Nobody pressed Done within N minutes, so the run stopped at this step. Nothing after it ran." (N comes from `HANDOVER_INCALL_MS`.) In a loop or branch it adds: "A hand-over inside a repeated or conditional step can't wait longer." Otherwise it throws `handoverPause` as today.
   - Resumed path (`run.js:948-954`): before consuming `__handover_done_<i>`, call `handover.revalidate(ctx.tabs, step, ctx.watch)` exactly as the in-call path does (`run.js:967-970`), and set `state.prevPage` to the page it returns.
   - `stepFailure` (`run.js:215-225`): copy `cause.handoverFailed` and `cause.handoverTimedOut`.
   - Fix the false comment at `run.js:1679-1683` (no patch_gate check exists; a pause in a loop now fails closed).
2. **Plain, terminal hand-over failures**: `runtime/app/handover.js`, `errors.js`, `failure_response.js`, `server.js`.
   - `handover.js::revalidate` (`:193-211`): keep `handoverRevalidationFailed` and add `handoverFailed: true`. Plain messages: "The page the person was working on was closed during the hand-over, so the run stopped. Nothing after this step ran." and "After Done, the page still didn't show what this step waits for, so the run stopped. Nothing after this step ran." Add `noPark()` = `process.env.CONXA_HANDOVER_NO_PARK === "1"`, read at call time so tests can set it.
   - `errors.js:40`: add `err.handoverFailed` to the deliberate-stop list, so the message is the summary.
   - `failure_response.js:600`: add `err.handoverFailed` to the fail-closed branch. In `haltReasonNoteText` (`:349-369`) add one line: "The run stopped at a step a person had to finish. Do not pick an element; tell the person what happened."
   - `server.js:2677`: add `&& !runErr.handoverFailed` to `parkable`. Next to the page_size block (`server.js:2635-2639`), when `runErr.handoverTimedOut`, set `_meta["conxa/couldnt_run"] = {kind: "handover_timeout", run_id, step_index}`. Studio already reads that meta as "not a result" (`workflows.py:1466-1472`).
3. **The result of a self-resumed run can be read (F3)**: `server.js:2579-2588`: pass `_run_id: _runId` in the self-resume args, as the sign-in continuation does at `server.js:777`. The final outcome is then recorded under the id the caller holds (`run_registry.js:147`, `continuation`). `handover.js::buildHandoverRequest` (`:226-231`): pass `opts.runId` and end the text with "To see how it ends, call get_execution_status with run_id: <id>." The pause itself is then also recorded as `paused`.
4. **Studio test never parks a hand-over (F7)**: `conxa-builder/python/handlers/workflows.py:589`.
   - Change `_TEST_RUN_ENV` to `{"CONXA_RECOVERY_PARK_TTL_MS": "900000", "CONXA_HANDOVER_INCALL_MS": "600000", "CONXA_HANDOVER_NO_PARK": "1"}`. That is 10 min inside the call, under the 900 s call timeout (`runtime_tool.py:262`) and the 30 min Studio run cap. Add a one-line comment saying why.
   - No new pause branch: past 10 min the runtime returns `conxa/couldnt_run` (item 2), and the existing branch shows "The test couldn't run … its last test result hasn't changed" with the plain reason. An older app layer ignores both env vars and parks after 10 min (today's behaviour, just later). Studio ships with the app layer in dev, so no capability gate.
5. **Banner survives navigation, shows only on the run's pages (F2, F8)**: `runtime/app/handover.js:57-120`.
   - `_bannerScript(message, bindingName)`: wrap the body in `add()`. If `!document.documentElement`, call `document.addEventListener("DOMContentLoaded", add, {once: true})` and return. Before drawing, `await window[bindingName]("ping")` and draw only if it returns true.
   - `arm()`: `bindingName = "__conxaHandoverDone_" + token`, so there is no clash with an earlier arm. Binding `(source, op) => op === "ping" ? (!settled && isRunPage(source.page)) : (isRunPage(source.page) && fire("banner"))`. `isRunPage(p)` is true when p is in `host.tabs.pages.values()`, is `page`, or was opened from one of those (`await p.opener()`, one level). Keep the context-wide init script; the ping decides where the banner shows. A stale init script after `disarm()` then draws nothing, because ping returns false once settled. `livePages()` in `disarm()` stays (removing a banner that isn't there is harmless).

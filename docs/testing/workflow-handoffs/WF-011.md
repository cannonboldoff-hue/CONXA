## Root causes and decisions
- **Loop cannot run in the local test lane (S1, tooling).** `scripts/build-app-local.ps1` line 111 lists the app layer's capabilities but omits `loop_rows`. `runtime/app/version.json` (source, since 2026-11-15) lists it, and compiled loop skills declare `required_capabilities: ["loop_rows"]`, so `runtime/app/server.js:1095-1098` refuses every loop test with "needs a newer Conxa engine". Installed layer: `~/.conxa-build-studio-dev/sandbox/.conxa/conxa-app/app-v0.0.0-local.*/version.json`. Fix is a one-word addition to the script's list (not done by tester: product/tooling file, and an attempt to patch the installed copy was blocked by the permission system, so I stopped). Needed to unblock: HP loop test, 11.8, 11.9, 11.10.
- Because of the above, the happy path loop run, row-N-in-record-N proof, approval, and 11.8-11.10 are unproven.
- Possible check gap in the loop (S2, unverified): in the saved loop body the Add click keeps `expected_text_tokens` ["Alice","Adams","alice@example.com","5000","Sales"] and three optional `text_present` checks frozen to row 1 (not rewritten to `{{row.*}}`). So the click would not prove rows 2..N even once the loop runs. Read from the saved skill, not yet run.
- Twin "couldn't confirm" on the last Add: records are correct in the page, but the run is failed by the "performed but not confirmed" rule. Not diagnosed further.
- Harness notes: the first OS click after focusing Studio becomes a double-click and the first record's last name was lost while recording r2/r3 (the page itself shows the empty last name in the recording-time fixture log), so the twin's Alice has an empty last name; replay matched the recording exactly.
- Studio exited by itself once (during a recording start, ~00:30); cause unknown.

### Fixer (2026-11-20)
- **F1 loop_rows missing (S1, root cause: copied capability lists).** `scripts/build-app-local.ps1` and `.github/workflows/build-runtime-app.yml` each kept their own copy of the capability list; the local one lacked `loop_rows`, the CI one lacked six (`wait_until`, `clipboard`, `call_workflow`, `agent_span`, `agent_span_v2`, `loop_rows`), so released app layers would also refuse those skills. Both now read `capabilities` from `runtime/app/version.json`. Guard: `conxa-cloud/tests/test_app_capabilities_source.py` fails if either build hard-codes a list.
- **F2 twin "couldn't confirm" on the last Add (S1, product defect, not a tester artefact).** The last acting step needs rung `completed`. Its proof was the person's three required "you see Cara / Clark / cara@example.com" checks, which count the words before and after the click. That count includes what text boxes hold. Before the click "Cara" was in the First Name box (1); after it the fixture copies it into the table and clears the box (still 1). No growth, so `cant_tell` x3 (telemetry `verify_result ct:3`), the completion gate saw no status region/request (`no_sign`), and the step ended `couldnt_confirm`. Adds 1 and 2 passed only because they are not the last step (rung `performed`). Alice's empty last name (tester artefact) is unrelated: it only affects row 1. Fix (`runtime/app/assertions.js`, `page_scripts.js`): the baseline also keeps `pageCounts` (page text without boxes, `countPageText`; `countTextEnding` takes `{text, pageOnly}` for bound record values); a text check is fresh when either count grew. Witness rule holds: a click that did nothing leaves the words in the box only, the page-text count unchanged, so the check would have answered "can't tell". "Step ran" is still never proof.
- **F3 loop body checks frozen to row 1 (S2).** `wrap_repeated_entries` rewrote checks only on the typing step itself. Now each column's first-copy literal is run through `_template_assertion_targets` (the rule `parameterize_literal` uses) over every body step: required/url/text checks naming it become `{{row.<column>}}`, optional text checks on a word of it are dropped. `success_conditions.expected_text_tokens` is left as is: nothing reads it after compile (runtime never sees it; `build.py` reads it only when compiling from events).
- **F4 newline in a one-line test box (S2).** Chosen behaviour: keep the text exact and say so. Pasting text with line breaks (or Shift+Enter) into a one-line Test inputs box turns it into a multi-line box with the note "This has more than one line. The line breaks are kept and typed as they are." Secret boxes unchanged. Note: a script that sets `input.value` directly (the tester's `notecase*.sh`) is stripped by the browser before Studio sees it; retest with a real paste or a dispatched `paste` event.
- **F3 completion (2026-11-20, second fixer session).** Review found two holes in the first F3 pass, both on the real saved skill (Add click checks `Alice` / `Adams` / `alice@example.com`, all optional): (1) columns were templated in recorded order, so `Alice` (first name) was replaced inside `alice@example.com` first, giving `{{row.first_name}}@example.com`; (2) `_template_assertion_targets` skipped any target that already held a `{{`, so a check naming two values ("Saved Alice Adams") would keep `Adams` frozen. Now the loop templates the longest first-copy value first, and the shared helper substitutes only outside existing `{{tokens}}`. Result on the real shape: `Alice` and `Adams` checks dropped (optional, a word of the value), `alice@example.com` becomes `{{row.user_email}}`. New test `test_wrap_templates_a_check_naming_two_values_and_a_value_inside_another`. `expected_text_tokens` left frozen on purpose (compile-time input only; `build.py` reads it from events, the runtime never does).
- **F2 review (2026-11-20).** Root cause confirmed from evidence: twin telemetry `verify_result si:38 n:3 ct:3`, and `rows.html` clears every box after copying it into the row. Fix kept as is. Witness rule check: the new test asserts "can't tell" before the click (words only in the box) and "yes, fresh" only after the row appears. The strict (record-ending) path compares a line-ending count after with a substring count before, which can only under-count growth, never invent it.
- **F5 addition.** The table-row error ("line 2: give 6 values separated by | (...)") now lists column names in plain words too (`test_flow.py::rows_from_text`).
- **F5 UX (cheap ones done).** Negative step count: chat line now "Your answers made it 26 steps shorter", card "(28 compiled, 26 fewer after your answers)". Table test input: the JSON default is shown as `a | b | c` lines (`rows_to_text` parses JSON text; before, Run test with the untouched pre-fill was refused by `rows_from_text`). Column names shown with spaces. Summary line cut to ~80 characters with the length. **Skipped:** the stale "5 quick questions / age 2, age 3" line and "I can't create a workflow myself" above a Create card are model-written chat text from before the loop answer, not code strings; changing prompts/order is risky for this pass. Also not touched: "12 more values left out" wording, "recorded values in to start" with an empty input, pre-ticked guard after "No, just do it", stale Recording card, failure card wording.

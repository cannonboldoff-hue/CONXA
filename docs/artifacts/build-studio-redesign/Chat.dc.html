Planning a refund workflow
Support approves refunds in the help desk, then someone re-types them into the billing portal. Could an agent do the billing part? Where do I start?
C

Yes — that’s a good fit. The billing part is a fixed sequence of screens, which is what a recorded workflow handles well. I’d keep the approval in the help desk and only automate the refund itself.

You’ll record it once: open the order, issue the refund, confirm. Afterwards I’ll ask which values change each time — almost certainly the order number and the amount — and whether a person should confirm before money moves.

One thing to check first: Finance Ops already has a Refund an order workflow. If it refunds the full amount only, a new workflow for partial refunds makes sense; otherwise you may just need a new input.

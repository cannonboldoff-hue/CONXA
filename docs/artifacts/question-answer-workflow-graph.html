Conxa Build Studio

How questions are made, asked and turned into edits

You record a workflow. Conxa then asks you a few questions, and your answers change the workflow. This page shows that whole path, step by step, in everyday words. Every box below matches real code in conxa-builder/python.

The whole journey in one picture

There are two rounds of questions. Round 1 happens before the workflow is built. Round 2 happens after. The big difference: in round 1 nothing can be edited yet, because the workflow does not exist, so your answers are only written down. In round 2 the workflow exists, so each answer edits it straight away.

Part 1: Where do the questions come from?

Two different "question makers" exist. Neither lets an AI invent edits. Code checks what was recorded and decides what to ask.

Round 1 maker

The video reader

A model watches the screen video and flags moments it is unsure about: "Is this value the same every time, or different each run?" Code then checks every question it proposes (timeline_understanding) and keeps only valid ones. Nothing is added by hand.

Round 2 maker

The workflow reader

clarify.generate_questions looks at the built workflow and runs detectors, with no model call. Example: it sees a popup in the recording and asks what to do with it. It sees a step that cannot be undone and asks to confirm before it runs.

Why two rounds? Some things are only knowable once the workflow exists, such as which steps repeat or which step cannot be undone.

Part 2: Which questions actually reach you?

A raw list of questions can be long and repetitive. Three filters keep it short. Think of them as an editor who strikes out questions that waste your time.

  1. Name the slot. Each question gets a label for the exact thing it settles (unknowns.annotate), for example "variability / value / event 14". The label uses recorded event ids, not step numbers, so it survives a rebuild that renumbers steps.
  2. Strike the useless ones. A question is "vacuous" if every answer would make the same edits, so asking cannot matter. A second question about a slot already asked is a duplicate. Both are removed (unknowns.vacuous, dedupe) when the ledger runs in "enforce" mode, and only counted in "report" mode. Safety questions are never removed.
  3. Score the rest. scoring.decide multiplies "chance the default is wrong" by "cost if wrong". Low score: keep the default quietly. Medium: keep it and mention it in the summary. High: ask. You can still say "ask me" to open the quiet ones. (Scoring is switched by the clarify_scoring setting: off, shadow or on.)

Learns your habits

If you keep giving the same answer for a kind of question on the same app, the chance of "wrong default" drops, so the next workflow asks less (answer_memory). It stores only the shape of the answer, never a value or page text. Safety questions ignore it.

Hard rules, not tunable

Safety floor: a decision popup, a step that cannot be undone, or an unsafe guess is always asked.

Round 1 is never assumed: before the build, nothing stands in for your answer.

Every asked question must be answered. No skip, no "later". An unanswered question blocks Test, Approve, Publish and Build Installer. At most 5 are shown at once; the rest come forward as soon as none is open.

Part 3: What happens when you answer?

Round 1 answers: written down only

In _pre_compile_answer your pick is turned into a small record (decisions.decision_from_answer): which question, which events, which choice. It is saved to the session folder. Your card turns green with a receipt, and the next question appears. When the last one is answered, the build starts. After the build, replay.plan matches each decision to the new steps and applies it using the same edit commands a button uses. If a decision matches nothing, Conxa says so in chat and never drops it silently.

Round 2 answers: applied straight away

What an answer can actually change

plan_answer never edits anything itself. It only returns a list of small instructions called "ops". The handler runs each op through the same commands a person uses in Human Edit. So chat, buttons and the editor all reach the same result.

Typing your own words

Yes, every question card has a text box under the options. It says "Or type your own answer and press Enter…" and takes up to 500 characters. The same box exists in round 1 and round 2. One question kind, "done when", has a different box (see the end of this section).

The key idea: your words are never a free-form instruction. Code (answer_from_words) only tries to read them as exactly one of the options on the card. It never guesses. If it can, that is the same as pressing the button. If it can't, nothing changes and the card tells you why.

Tick-list questions (several can apply)

Type the option names, or none, or all / everything / both. Every word must be understood. "Full name and email" only counts if both are real options, so an email is never dropped silently. A leftover word it cannot place, or a mix such as a name plus "none", is refused and you are asked to tick instead.

What typed words can not do

They cannot add a new step, rename something, or point a step somewhere else. Those requests ("also wait 5 seconds", "click the other button") do not match any option, so the card refuses them. Say them in the workflow chat instead, where the change shows as a proposal you can Apply or Undo, or make the change in Human Edit. If you type into the main chat while a question is open, Conxa answers "Still need your answer: the question title" and the question stays open.

The "done when" exception

This question asks what you should see on the screen when the workflow worked. Its box says "Or type words you should see on the screen when it works" and takes at most 120 characters. Those words are not matched to an option. They are sent along as the check text (custom_text) and become a check that the words appear on screen. Longer text is refused, never cut in half, with: "Type a shorter part of what you see on the screen."

Going back and getting new questions

The pencil (undo an answer)

Before each round 2 answer, the workflow is saved as a snapshot. The pencil restores it and reopens the question. Round 1 questions are archived (pre_questions.json) so the pencil can rewind to them too, which rebuilds the workflow.

Follow-up questions

An answer can change the workflow so that a new question makes sense. After each edit, _flow_reevaluate runs the detectors again, with no model call, and adds only questions not asked or settled before.

Rebuilds

If the workflow is rebuilt, answers that match the same situation are carried over (_flow_carry_settled) instead of asked again. Questions about steps that no longer exist are marked stale.

Friendlier wording

Questions go out in plain template wording first. A model rewords them in the background afterwards, and every reworded field is validated, so a question never waits on a model.

Where Claude's design wins

  • Nothing to compile or maintain: record, then save.
  • It adapts to moved buttons and unforeseen branches without anyone editing it.
  • It covers one-off and fuzzy tasks.
  • Narration is a cheap, rich channel for intent.

Where CONXA's design wins

  • Every normal run uses zero tokens and the same actions, which a SaaS vendor can promise its customers.
  • Declared, typed inputs become an MCP tool schema.
  • Compiled assertions check outcomes, not judgement.
  • The author settles ambiguity once; it is never improvised during a customer's run.
  • It runs under any MCP agent and syncs to many machines.

What CONXA could borrow

Proposed

Narration as a timed intent track

Record audio, transcribe locally, align utterances on the event clock, pass them to build_input as timed chat. "This changes every month" then lands on its row instead of becoming a question.

Proposed

A prompt twin for every skill

Export the intent graph goal and per-step prose as a readable prompt next to the compiled steps. Tier B and ai_review get a stable statement of intent; authors get an editable summary.

Proposed

Compile from a successful agent run

Claude turns a finished chat into a shortcut. CONXA could turn a Tier B recovery that worked into a re-target, or an exploratory agent session into a segment, via cmd_splice_segment.

Proposed

Plan approval before the first real run

Show the compiled plan with irreversible steps marked and let the person approve it once, like "Approve plan". Complements the per-step guard.

Proposed

Schedule from Studio

The runtime already has a local scheduler (scheduler_daemon.js, create_schedule); Studio has no screen for it.

Proposed

An agent span for fuzzy middles

Let an author mark one span "let the agent do this part" while the rest stays deterministic, under the same guard and invariants as ai_review.
